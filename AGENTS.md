# True Proxy

Общайся с пользователем по-русски, если он не попросил другой язык. True Proxy — нативный Windows x64 EXE для прозрачной маршрутизации TCP/UDP по процессам через несколько SOCKS5-прокси. Стек — Rust, Slint с software renderer и WinDivert 2.2.2. Изолируй Windows API и `unsafe` в платформенном слое с учётом будущего macOS backend.

## Разработка и проверка

- Команды и статус проверок — [README.md](README.md#разработка-и-проверка). Используй локальный `.tools`, `scripts/bootstrap.ps1` и `scripts/dev.ps1` (`check`, `test`, `clippy`, `smoke`, `build`, `package`). Не меняй глобальный PATH.
- После изменений приложения собери локальный EXE и дай путь к нему. `Test-Local.cmd` использует копию профиля и модулей с ручным включением Xray и маршрутизации. Для образца UI есть `scripts/dev.ps1 preview -Page xray`. Публикуй релиз только по явной просьбе.
- Обычные тесты, smoke и замеры работают без UAC и реального перехвата. Сетевые проверки проводи на искусственных пакетах, локальных фикстурах или в изолированной сети. Перехват рабочего трафика, изменение маршрутов и настоящее DHCP-продление требуют изоляции или согласования. Не закрывай рабочее приложение и не перезапускай Проводник ради тестов.
- Проверяй затронутые сценарии TCP, UDP, DNS, IPv6, порядок правил, отказ SOCKS и остановку. `UDP ASSOCIATE` проверяй отдельно. Smoke и `driver_abi` не подтверждают сквозной перехват. Указывай ограничения проверки в README и отличай измерения запуска, RAM/CPU в трее, задержки и пропускной способности от оценок.
- Сохраняй минимальные зависимости, размер EXE и накладные расходы. Без Electron, отдельного Chromium, WebView, телеметрии и новых фоновых запросов без требования пользователя. Применяй правила в backend, отдавай UI агрегаты, ограничивай журналы, историю и очереди.

## Маршрутизация и конфигурация

- Используй существующий WinDivert backend в [src/platform/windows/](src/platform/windows/). Сохраняй приоритет полной пары DLL/SYS рядом с EXE над встроенной, атомарно извлекаемой парой. Не ищи DLL по CWD. Исключай петли собственных соединений точечно, без обхода по похожим именам процессов.
- Системный DNS по TCP/UDP :53 всегда Direct, DoH/DoT следуют правилам. Валидный DHCPv4/v6, включая broadcast/multicast, пропускай до атрибуции и лимита потоков, проверяя содержимое. Не меняй DNS адаптеров, таблицу маршрутов или системный HTTP-прокси. Старые DNS-поля читай для совместимости, при сохранении опускай. Без injection, hooks и Fake-IP.
- Для остального трафика первый блок — локальные CIDR, всегда Direct для любого владельца, в том числе при полном кэше. У блока редактируется только список CIDR, который хранится отдельно и переживает переносимый импорт. Далее действуют первое совпавшее включённое правило и явный fallback. Условия разных типов — AND, значения одного типа — OR. Дочерние процессы оценивай отдельно. Сохраняй имя EXE или полный путь, PID только справочный.
- Подтверждённый PID 4 — `System` с пустым путём, обычные правила без исключения для SMB. Неизвестного владельца вне локальных CIDR жди в ограниченной очереди до 3 с, затем Direct. TCP сохраняет решение до закрытия, UDP повторяет атрибуцию не чаще раза в 2 с. Ошибка SOCKS не переводит трафик в Direct без явного разрешения. В UDP проверяй маршрут каждого peer и сохраняй реальный адрес отправителя.
- Домены сопоставляй по ограниченному TTL-кэшу наблюдаемых DNS-ответов. `example.com` — точное имя, `*.example.com` — домен и поддомены. Сохраняй миграцию v1 → v2 с резервной копией. В журналах показывай сработавшее правило и известные имена или отсутствие имени.
- Валидируй конфигурацию и ссылки целиком до атомарной записи. SOCKS-пароли защищай DPAPI, исключай из журналов. По явному экспорту переносимый JSON включает открытые пароли, прокси, правила и fallback. Импорт сохраняет локальные CIDR, `routing_enabled`, автозапуск и настройки обновлений. Не удаляй используемый прокси без разрешения зависимостей.
- Сохранение настроек не меняет активный snapshot. Показывай общее уведомление Restart только при неприменённых изменениях. Перезапускай по явному нажатию, предупреди о разрыве соединений и убери уведомление после подтверждения backend. Закрытый toast с требуемым действием остаётся в колокольчике.

## Интерфейс и жизненный цикл

- Переиспользуй `Theme` и компоненты [ui/common.slint](ui/common.slint) и [ui/notices.slint](ui/notices.slint). Английские подписи, нативная шапка Windows, Connections в том же окне, тёмная тема по умолчанию с сохранением выбора. Settings содержит General и Modules. Для всех чисел используй `NumericText`, `Badge.numeric` или `Theme.numeric-font`.
- Сохраняй `Theme.page-gutter` 26 px и общие `IconTile`, `CountBadge` и `RuleSwitch`. В General разделяй Theme и Surface Effects, в узком окне ставь их друг под другом. Application updates и Startup занимают всю ширину. Карточки Modules переиспользуют [ui/module-card.slint](ui/module-card.slint) и показывают фактический прогресс загрузки.
- Настройки Sidebar и Notifications независимы. Mica и Acrylic ограничены боковой панелью и левой частью заголовка, справа фон непрозрачен. Acrylic по умолчанию 30% и Frost 32/32, при Frost 0 детали окон остаются чёткими. Уведомления применяют выбранные прозрачность и размытие с первого кадра, исходные значения 48% и 9 px.
- Xray Dashboard показывает ядро, события и локальные SOCKS-порты. Профили, подписки и активные узлы редактируются в X-Ray → Profiles. В селекторе порта шириной 220 px пять цифр должны помещаться при любой длине названия.
- Проверяй обе темы при 1240×780 и 960×640, длинные значения, прокрутку, фокус и первый клик реальными событиями мыши. Статусы берутся из backend, Sample data только для preview. График хранит до 121 точки за 120 с и продолжает сбор до 120 с после ухода с Dashboard в видимом окне. В скрытом окне останови обновления UI, при возврате убери устаревшие точки без усреднения пропуска.
- Обычный запуск получает UAC до создания UI и восстанавливает `routing_enabled`. При повышении передавай `--enable` только если он явно задан. Автозапуск использует собственную задачу Планировщика с `--tray`. Закрытие окна оставляет один экземпляр в трее, повторный запуск открывает его окно. Трей открывает окно, меняет паузу и завершает приложение. Активность показывай после подтверждения backend, сбой показывай сразу. Ручную паузу и подтверждённый сбой сохраняй. При выходе освобождай перехват без изменения сохранённого состояния.
- Connections показывает реальные сеансы по EXE. История собирается только на видимой неминимизированной странице и очищается при уходе. Фильтры и видимость не влияют на сетевой учёт и кэш решений. Подробности состояний, лимитов и закрытия сокетов — в [README.md](README.md#соединения), [src/connections.rs](src/connections.rs) и [src/udp.rs](src/udp.rs).
